# KeepFacts session format v1

KeepFacts can explicitly export the current workspace as a
`.keepfacts.json` file and import it later. Version 1 is a strict interchange
format for editor text and human review records. It is not a cache of trusted
comparison output.

> **Privacy warning:** a session is unencrypted UTF-8 JSON. It contains the
> full source, rewrite, must-preserve content, and any exported human decisions,
> notes, and expected fixes. KeepFacts does not automatically save or upload
> this data, but exporting starts a browser download. The download folder,
> cloud storage, backups, indexing, or security software may copy or synchronize
> the file.

## Minimal valid session

```json
{
  "format": "keepfacts.session",
  "schemaVersion": 1,
  "exportedAt": "2026-08-13T08:30:00.000Z",
  "generator": {
    "appVersion": "0.3.0",
    "commitSha": "local"
  },
  "privacy": {
    "containsFullText": true,
    "encrypted": false
  },
  "locale": "en",
  "editor": {
    "source": "The filing deadline is 20 August 2026.",
    "revision": "The filing deadline is August 20, 2026.",
    "required": "filing deadline"
  },
  "result": null
}
```

All fields shown above are required. Unknown fields are rejected at every
object level. `result: null` represents an editor draft without an exported
checked result.

## Exact schema

The root object has exactly these fields:

| Field | Required value |
| --- | --- |
| `format` | Literal string `keepfacts.session` |
| `schemaVersion` | Integer literal `1` |
| `exportedAt` | Valid UTC timestamp in exact `YYYY-MM-DDTHH:mm:ss.sssZ` form |
| `generator` | Exact object `{ appVersion, commitSha }` |
| `privacy` | Exact object `{ containsFullText: true, encrypted: false }` |
| `locale` | `zh` or `en` |
| `editor` | Exact input object `{ source, revision, required }` |
| `result` | `null` or the exact result object described below |

`generator.appVersion` must be a semantic version without a leading `v` and
must not exceed 64 UTF-16 code units. `generator.commitSha` must be the literal
`local` or a 7–40 digit hexadecimal commit SHA and must not exceed 40 UTF-16
code units.

The `editor` object is the text visible in the editor when the session is
exported. Its three fields are strings. `required` is the newline-separated
must-preserve input.

When `result` is not `null`, it has exactly two required fields:

```json
{
  "input": {
    "source": "the source used for the last check",
    "revision": "the rewrite used for the last check",
    "required": "one must-preserve item per line"
  },
  "reviewRecords": [
    {
      "key": "opaque key generated by KeepFacts",
      "decision": "confirmed",
      "note": "Optional reviewer reasoning",
      "expectedFix": "Optional correction requested"
    }
  ]
}
```

`result.input` has exactly the same shape and limits as `editor`. It records the
input used for the last completed check and may differ from `editor` when the
user has edited the current draft since that check. A comparison object, counts,
retention percentage, and fix list are deliberately not serialized. On import,
KeepFacts runs `result.input` through the current local comparison engine again.

Each `reviewRecords` item has required string field `key` and may contain only
these optional fields:

| Field | Accepted value |
| --- | --- |
| `decision` | `confirmed`, `accepted`, or `ignored` |
| `note` | Reviewer text |
| `expectedFix` | Requested correction text |

Review keys are opaque identifiers generated by KeepFacts for a checked input.
Consumers must not construct, shorten, or infer meaning from them. Keys must be unique
within the array. After the comparison is recomputed, KeepFacts restores only
records whose exact key exists in the current review queue; unmatched records
are discarded rather than attached approximately. A record with no decision,
non-empty note, or non-empty expected fix is omitted from the normalized
session. Records are serialized in key order for deterministic output.

## Limits

Lengths below are JavaScript UTF-16 code units unless stated otherwise. Limits
apply independently to `editor` and `result.input` where both are present.

| Data | Maximum |
| --- | ---: |
| Complete serialized session | 5,242,880 UTF-8 bytes (5 MiB) |
| `source` | 250,000 code units |
| `revision` | 250,000 code units |
| `required` total | 100,000 code units |
| Non-empty must-preserve items | 1,000 |
| One trimmed must-preserve item | 500 code units |
| Review records | 3,000 |
| Review-record key | 1,024 code units for ordinary keys; a generated must-preserve key may be longer only up to the length derived from its normalized `result.input.required` item, with an absolute 9,022-code-unit guard; not empty |
| `note` | 500 code units |
| `expectedFix` | 500 code units |
| Extracted facts in each `result.input` side | 1,000 |

The fact-count limit is enforced by the current engine before its global
pairing stage. A normal comparison uses the same limit, so a checked result
that KeepFacts exports remains eligible for import under schema v1. Draft-only
sessions (`result: null`) are not compared during import.

Must-preserve items are split on LF or CRLF, trimmed, and empty lines are not
counted toward the 1,000-item limit. Notes and expected fixes are trimmed; LF
and TAB are allowed, while other C0 and C1 control characters are rejected.
Generated must-preserve review keys include an NFKC-normalized item. Because a
valid 500-code-unit item can expand during NFKC normalization, the parser derives
the accepted generated-key length from the corresponding checked input. This
keeps schema-v1 files round-trippable without allowing unrelated oversized
opaque keys; consumers must continue to treat keys as opaque.

The parser also rejects malformed JSON, incorrect scalar or container types,
missing fields, unknown fields, duplicate review keys, invalid enum values,
invalid timestamps, unsupported schema versions, and files over the byte limit.
A leading UTF-8 BOM is accepted. The browser importer additionally requires a
non-empty filename ending in `.keepfacts.json`; its fact-count guard is applied
before comparison pairing begins.

## Import and compatibility rules

1. The complete file is size-checked, parsed, and validated locally before the
   current workspace is replaced.
2. If `result` is present, KeepFacts recomputes that saved input locally with
   the current fact engine. Serialized text is never treated as authoritative
   comparison output.
3. Human records are restored only by exact current review key. Records that no
   longer identify a reviewable finding are reported as unmatched and dropped.
4. `editor` then restores the current draft, which may intentionally be newer
   than `result.input`.

Version 1 readers accept only `schemaVersion: 1`; they do not guess how to read
a future schema. A future incompatible format must use a new schema version.
Because unknown fields are rejected, producers should not add private extension
fields to a v1 session.

The format provides validation and deterministic interchange, not encryption,
authentication, or proof of origin. Treat imported sessions as untrusted files
and exported sessions as sensitive plaintext.
